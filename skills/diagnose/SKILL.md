# Diagnose

Owner-facing reply: each AI chooses its complete intended response, including detail, evidence and disagreement. Relay Codex's answer and flags unedited under its speaker label; do not substitute a summary or impose brevity or omission rules. Deliver every unread answer, including earlier phases. Use controller relay to retrieve it. Missing delivery is recoverable bookkeeping, never a reason to trap a reply or block unrelated authorized work. A stored answer or hook reminder is not proof of visible delivery. Wait in bounded slices for active partner work; a timeout does not complete the task.

For an attachment problem, verify the current hook-recorded session matches the upload's session directory and that `CLAUDE_CONFIG_DIR` is honored. Do not scan uploads or inspect them outside the Image review assignment. Forward the current host-provided reference through Phase 1 and check indexed attachment delivery. A validated path alone is not proof of delivery.

Report activation from runtime evidence, not package version alone. The SDK sandbox selection does not layer permission-profile deny rules. Host prompt rewrites are not guaranteed; do not claim they isolate expanded command arguments.

Report `codex.model` source and verification status. A configuration default is not proof of the served model; unknown stays unknown. The `fabex` source applies only to new threads and does not certify Desktop invisibility. A returned hook rewrite does not establish that the host applied it.

Run `node ${CLAUDE_PLUGIN_ROOT}/scripts/control.mjs diagnose` from the project root. Report the factual activation block: source and registry versions, match, hook validity, reload requirement or unknown, last recorded turn/version, and verdict. Also report state health, safe lock metadata, SDK installation, repository root, network switch, and broad command warnings. Use diagnose to check activation after an update. Confirm the stable evidence, lifecycle, compaction, wake, and owner-mode-grant hooks are registered. Never claim activation when the verdict is unknown or unverified.


## Message and attachment handling

Use `controller.mjs relay --operation-id <uuid>` to obtain only the exact relayBlock, and paste it unmodified. Ordinary both-participant image-only requests use `ownerMessage: ""` with attachments; mode uploads use repeated `--attach` arguments before grant consumption. Prefer `previousReplyStatus: "recorded"`; unavailable evidence must be reported, not invented or truncated. Discussion/Ask writes must stay within the effective activity policy: validated research locations and text plans when permitted, or external scratch/memory roots. Application edits remain denied. Image restrictions remain in unhealthy states. Report attachment delivery from recorded status; do not infer successful forwarding from a valid path alone.

Inspect `diagnose.claude.lastSessionStart` for the bounded source and model-field status, and `diagnose.claude.explanation` for the honest fallback. Same-session model-less starts retain prior evidence; PostModelSwitch recaptures `to_model` on supported hosts. A session model is not proof of the model serving every response.
